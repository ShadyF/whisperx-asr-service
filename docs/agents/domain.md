# Domain Docs

## Before exploration

Read root `GLOSSARY.md` and relevant decisions in `docs/adr/` before exploring a domain area. If `GLOSSARY-MAP.md` exists, follow it to relevant context glossaries and decisions.

When these files do not exist, proceed silently. Domain-modeling creates them lazily when terms or qualifying decisions are resolved.

## Layout

This repository uses one context: root `GLOSSARY.md` and `docs/adr/`. Setup does not create empty domain documents.

## Vocabulary and decisions

Use glossary terms consistently in code discussions, specs and issues. Flag contradictions with existing ADRs explicitly before proposing a conflicting design.
